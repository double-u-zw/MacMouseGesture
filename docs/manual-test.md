# 横向手势验收清单 · 0.1.4 / Build 6

此清单按批执行，不要求一次做完。自动化合成输入通过不等于下面的实际 Spaces 测试通过。

## 当前证据

- 开发环境已验证：A → B → Build 5 → Build 6 在首次签名迁移授权后保留 Accessibility；Build 5、6 两项权限均 true。
- 开发环境已验证：设置 720 / 13、退出重开仍保持；恢复 600 / 8；手动停止后重开仍停用；再次显式启用恢复。
- 40 项自动检查通过，包含原有 28 项；真实睡眠、多屏与全天稳定性仍需人工验证；用户已确认连续操作正常，当前进程记录超过 100 条完整手势。
- Build 4 偶发失效原因未定，Build 6 的诊断用于继续区分输入缺失、Tap 停用、状态机与投递阶段。

## 准备与记录

1. 至少两个 Space；使用同一个鼠标，记录有无其他鼠标映射工具同时运行。不要为了测试擅自改动其他应用设置。
2. 默认值是两个 CG 按键 `3,4`、Invert=true、pixels/progress=600、dead zone=8、Freeze=true。两键重叠采用 Build 4 的“第一颗按下开始，最后一颗松开结束”。
3. 每批前后各复制一次诊断。为了做完整 100 次累计，开始前完全退出后重开；测试中不要退出应用。手动重新开启引擎不会清零累计值。
4. `progress` 是内部协议比例，不是已校准的桌面百分比。肉眼的半程位置为准。单次按住应少于 20 秒，以免触发既有保护。

## 第一批：最重要的两个操作

- [x] C1 / C2（用户确认）：侧键按住，极慢地向左拖至半程；保持按下停 2 秒，再继续拖，松开。连续跟随，中间保持，只有一次 began 和一次终止。换另一颗键、另一个方向再试。
- [x] C8（用户确认）：Button4 / Button5 交替，共 20 次左右拖。两个键均有效，松手后指针可正常移动，不需要重新开启。

## 第二批：方向与释放

- [ ] C3：先向左约 100 px，再向右约 80 px。进度自然回退，仍是同一手势，不出现第二个 began。
- [ ] C4 / C5：按住轻微往返抖动；未出死区不启动。再逐渐超过死区，只开始一次。精确 7+2 px 已用自动测试覆盖，手工不要求量出像素。
- [ ] C6 / C7：短快速 flick；另做慢拖并在松手时轻微抖动。松手只能有一个 ended 或 cancelled，之后不能再有该手势的 changed。短慢拖回弹属于正常取消，不能把所有 cancelled 都算故障。

## 第三批：双键与日常恢复

- [ ] C9：4 按下拖动 → 5 按下 → 松 4 → 继续拖 → 松 5。只形成一段手势。交换按下顺序与松开顺序再试。
- [ ] 关闭面板后继续用；Dock 图标重新打开；睡眠/唤醒后再用。主动停止后，唤醒不应擅自启用。
- [ ] 若有多屏，改变显示配置后检查恢复；不以一次系统通知的模拟代替硬件验收。

## C11 / C12：性能

本轮结果：活动 CPU 有效采样10.4%–15.5%；关闭面板后最后一组后台样本3.1%–7.5%。未在同一采样窗口确认输入计数不变，因此“严格空闲接近0%”仍未验收，不能将单个0.0%视为通过。RSS 在141条手势后为112.1 MiB，后来154条时回到85.6 MiB；尚无本段持续线性增长的证据，也不代表长期无泄漏。

- 不移动鼠标、开启引擎观察至少 10 秒，记录 CPU。分别记录设置面板可见和关闭时的值。
- 将采样起止时间与 rawMouseEvents 对齐；采样期间不要读取会重新打开窗口的 UI 自动化接口。先确认进程仍在、引擎开启，缺失进程不能算0%空闲。
- 连续拖动时记录 CPU 区间和采样峰值，不能把启动峰值或全进程平均值当作每帧开销。
- 保存开始、20、40、60、80、100 次后的 RSS。诊断会自动保留每跨过 100 个终止手势时的 RSS 检查点（最多 10 个）；内存日志最多 300 行。
- 启动后 AppKit、字体与诊断布局的正常分配可能增长；至少看多组趋势。只有 100 次的一前一后两个数，不能单独证明无泄漏。
- 内置 CPU 使用进程 CPU 时间差 / 墙钟时间差，100% 表示一个核心；约 1 秒采样。RSS 是常驻内存。不能用这两个数冒充硬件延迟或瞬时峰值。

可选命令，只采样这个进程：

```sh
pgrep -x MacMouseGesture
# 将上一步 PID 填入：
top -l 6 -s 2 -pid PID -stats pid,command,cpu,mem,threads
```

## C13 / C14：诊断含义与再次失效时

- `rawMouseEvents`：当前进程各次启用累计收到的鼠标按键、移动、滚轮回调数；不计键盘。
- `coalescedFrames`：成功送入 bridge 的 began + changed；terminal 单独计入 end/cancel。
- `Button4Downs / Button5Downs` 与最后侧键时间：区分没收到侧键和收到了却没开始手势。
- `Event tap: enabled` 是系统 Tap 开关状态，不保证上游没有其他工具吞事件。
- 超时禁用、用户输入禁用都先 fail open，取消当前手势一次，再尝试 `CGEvent.tapEnable`。每 60 秒最多 3 次尝试；失败明确停止。成功增加 `eventTapRestarts`，不会续接原手势；先松开旧的侧键再操作。
- 另外每秒检查一次 Tap 是否禁用或失效，不会因鼠标安静而主动重启。系统实际触发禁用后的恢复仍待硬件现场验证；自动测试覆盖了中断、释放隔离、频率上限及终止计数。
- 若失效，**先复制诊断，再点重新开启**。记录：是否发生睡眠/切屏、两颗键是否都失效、侧键计数是否增长、gestureState、HID 是否还记录侧键。恢复以后再复制一次，避免丢失故障前状态。
