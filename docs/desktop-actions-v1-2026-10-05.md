# 锁屏与访达动作 · Build 31

2026-10-05，按用户要求加入锁屏、打开访达、新建文件夹。用户明确确认“在访达当前文件夹新建”。当前独立 Build 31 已运行，保留 Prototype v2 三列主界面及全部旧应用包，未安装覆盖或发布。

## 行为

| 动作 | 执行方式与范围 |
|---|---|
| 锁定屏幕 | 复用原执行器的 Control + Command + Q 键盘事件对。 |
| 打开访达 | 使用 NSWorkspace 的文件浏览器 API 激活访达，并打开个人主目录窗口；访达未运行时由系统打开。 |
| 新建文件夹 | 仅在访达前台时，将 Command + Shift + N 事件对发送给该访达进程；由访达在当前目录创建空文件夹并进入命名。其他应用前台时不发送事件、不激活访达。 |

新建文件夹会复查前台进程和辅助功能权限；切换应用、访达进程改变或权限不可用时放弃。完整事件对在发送前创建，并定向给已捕获的访达 PID，不发送到全局键盘流。访达对目录可写性、搜索视图等限制继续生效；事件已提交不等于文件夹创建已验收。

打开访达的 AppKit 操作通过主队列异步执行，避免与主界面的引擎快照读取互相等待。日志区分已排队与系统实际返回的成功或失败。

快捷键依据：[Apple 的 Mac 键盘快捷键说明](https://support.apple.com/en-us/102650)。文件浏览器 API 的行为同时核对了本机 SDK 中 `NSWorkspace.h` 的声明与说明。

## UI 和配置

三项动作同时出现在主表动作菜单和添加、编辑弹窗。弹窗显示打开访达的目标及新建文件夹的作用范围。可以用于已有的短按、长按、修饰键组合和按住滚轮操作；连续拖动仍为固定的触控板式手势。

锁屏已有 `system / lockScreen` 配置值；新加 `system / openFinder` 和 `system / newFolder`，沿用原字段、序列化结构和配置版本，没有改 MappingStore 或迁移实现。旧开发版无法执行这两个新值，会按既有未知动作策略读取为无操作。

没有自动绑定或覆盖用户映射。新增动作执行器和分发以外，输入监听、PressClaim、adapter、录制器及手势核心未修改。
