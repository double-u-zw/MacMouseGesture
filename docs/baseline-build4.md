# MacMouseGesture 项目总结与后续计划

更新：2026-09-29。此文件汇总当前状态；历史研究见 [research.md](research.md)，逐轮证据见 [validation.md](validation.md)，操作方式见 [README](../README.md)。

## 当前结论

已经完成一个能在用户当前 Mac 上实际使用的原生横向鼠标手势版本。用户明确反馈“可以正常使用了”；两个侧键、当前方向和持续运行的基本功能通过。距离长期稳定的完整 MVP，仍缺纵向手势、设置持久化、稳定的更新授权流程、正式菜单栏及完整硬件/系统边界测试。

当前阶段是 Phase 2 横向 POC 基本验收通过。后续仍围绕“侧键作为触控板手势修饰键”，不扩展窗口管理、宏、剪贴板等无关功能。

现有回归总计 **28 项，0 失败**，结果在 `build/test-output-build4.txt`。最新用户诊断在 `build/continuous-feedback-build4.txt`，包含 40 次完整 began/ended 序列：cg=4 为 38 次，cg=3 为 2 次，无 ERROR、cancelled 或队列溢出记录。

## 代码结构

| 位置 | 职责 |
|---|---|
| `Sources/GestureCore/GestureMachine.swift` | 无系统 API 的手势状态机、进度与速度计算 |
| `Sources/MouseGesturePOC/MouseInput.swift` | CGEventTap、按键归一化、双键逻辑按住、有界累计队列 |
| `Sources/MouseGesturePOC/GestureEngine.swift` | 串行调度、帧合并、后端投递、取消与退出清理 |
| `Sources/MouseGesturePOC/AutoStartState.swift` | 自动启动意图与多个挂起原因；避免覆盖手动停止 |
| `Sources/MouseGesturePOC/HIDInputBackend.swift` | 可选只读 IOHIDManager 设备/按键对照与断开观察 |
| `Sources/MouseGesturePOC/main.swift` | POC 面板、参数读取、权限提示、应用生命周期 |
| `Sources/SystemGestureBridge/` | 唯一私有 API 边界，HID DockSwipe 构造、附加、回读与发送 |
| `Tests/CoreRegression/` | 状态机、输入流水线和自动启动回归 |
| `scripts/` | 构建、测试、工具链与防止覆盖运行中应用的锁 |

输入流程：`CGEventTap → 有界位移累计/按键边沿 → 串行引擎 → 约 120 Hz 手势帧 → SystemGestureBridge → Dock/WindowServer`。

私有 API 集中在桥接模块，采用运行时加载。`references/mac-mouse-fix/` 只作研究参考，不参与编译；来源和许可情况已记录在 `THIRD_PARTY_NOTICES.md`。

## 已解决的问题

- 辅助功能开关打开却返回 false：读取系统日志确认过旧 ad-hoc requirement 与新代码签名不匹配；对当前应用定向清理旧记录并重新授权后恢复。
- 侧键命名混淆与只能用一颗键：保留 CG 原始编号，并按用户要求将默认绑定扩为 `3,4`。
- 左右方向相反：使用反转配置，用户实测确认后设为默认。
- 每次需要重新开启：取消横向模式 120 秒限时，增加授权后自动启动与面板关闭后驻留。
- 异常事件时间戳：状态机改用回调到达的单调时间，避免零/旧时间戳误触发安全限时。
- 构建覆盖运行中应用：脚本和应用共享进程锁，运行中拒绝覆盖；旧版本已保留项目内归档。

| 优先级 | 工作 | 具体完成标准 |
|---|---|---|

| P0 | 横向稳定性验收 | 100 次真实左右切换、慢拖停住/反向、两键重叠、停止/恢复；无卡住、误触、提前结束或遗留输入拦截；记录 CPU/内存 |
| P1 | 纵向 POC | 分别验证向上 Mission Control、向下 App Exposé 的 began/changed/ended/cancelled；保持可回退的横向基线，实测连续跟随 |
| P1 | 日常使用界面 | 简单菜单栏：启用、设置、诊断、重启引擎、退出；状态明确区分等待授权、运行、主动停用和异常停用 |
| P1 | 权限及诊断整理 | 按实际使用的输入后端说明权限；区分自动符号探测、事件投递与人工验收，避免通过后仍被 `UNVERIFIED` / `acceptance pending` 文案误导 |
| P1 | 登录启动 | 在用户选择并允许相应系统配置变更后实现；验证开启、关闭、重新登录与退出行为 |

优先稳定更新与保存设置，再补横向边界验收，随后进入纵向。这样后续每轮改动都有可重复的安装、启动和验收流程。

## 需重点复查的交互细节

- **锁轴容错：** 当前跨过死区后立即锁轴。历史日志出现总横向位移很大但未发手势的一次操作，可能为起手竖向分量先触发拒绝；缺少原始轨迹，尚未确认为故障。需要小斜角/按键抖动实测。
- **松手判定：** 当前反向速度超过阈值即可导致取消，历史日志有接近目标进度时因反向速度而 cancelled 的例子。用户已明确此前方向问题只是左右反向，不能把该条日志当成已确认的回弹缺陷；仍应测试微小松手抖动与有意反向的区别。
- **“取消一次”与“停用工具”：** Escape、连续按住 20 秒、tap 异常等当前会停止引擎；显示配置变化也会停止。后续应明确哪些只取消当前手势、哪些需要手动恢复，并测试与睡眠唤醒自动重启的关系。
- **进度标定：** `pixels/progress` 是内部协议比例，不是已标定的桌面切换百分比；需要跨显示器尺寸、分辨率和 Space 边界验证。
- **指针体验：** 已实现通过事件拦截冻结；冻结/正常移动对照、屏幕边缘、松手跳变尚未全面验收。
- **设备断开：** 未开启可选 HID 观察时，不能承诺即时知道鼠标被拔出，目前还有按住时限保护。
- **性能：** 引擎空闲没有 120 Hz gesture timer，但面板诊断仍每秒刷新；不能仅据实现方式宣称 CPU 接近 0，需要实际 profiling 后再优化。

## 构建与后续开发约束

当前构建入口：

```sh
./scripts/test.sh
# 先在应用中按 ⌘Q 完全退出；关闭面板不足以退出。
./scripts/build.sh
open build/MacMouseGesture.app
```

本机 Swift 6.4 新 driver / SwiftPM 与中文项目 TMPDIR 的兼容问题尚未解决，脚本使用同一工具链的 legacy driver；`swift test` 不是本机验收入口。Package.swift 的最低平台描述目前仍为 macOS 14，实际 bundle 与构建目标是 macOS 27，应在构建整理时统一，不能据此声称支持 macOS 14。

后续实现应在当前项目内完成，保留正在使用的 Build 4 基线，准备好必要改动和测试再集中发布新构建。当前总结没有重新编译、签名、重置权限或修改运行设置。

稳定证书、钥匙串、登录项等方案可能涉及项目之外的系统配置；必须明确具体方案及影响，再取得对应授权。此前允许过的单次 TCC 重置不代表可无限重复操作系统权限。

**建议下一轮范围：稳定更新授权方案 + 配置保存 + 横向边界验收。** 不在同一轮混入纵向和完整设置界面，便于定位任何回归。
